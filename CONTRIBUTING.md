# Contributing

The interface, the shared catalogue and the agents are developed in the open
here. The simulation lives in a private monorepo, and this repository is
generated from it — which changes one thing about how a pull request lands.

## How a change reaches the game

1. Fork, branch, change what you want in `client/`, `shared/`, `agents/` or
   `public/`.
2. `npm run dev` and try it against the live world. `npm test` and
   `npm run typecheck` before you push; the same checks run on your pull
   request.
3. Open the pull request here. Discussion and review happen on it.
4. An accepted pull request is applied to the monorepo **with your commit
   authorship intact**, and the next publish brings it back into this
   repository under your name. Then the pull request is closed with the commit
   it became — closed, not merged. A merge here would be reverted by the next
   publish, which is why the button stays untouched.

So your work does reach players, and the history here keeps your name on it.

## What can change here

- `client/` — anything: layout, controls, rendering, sound, performance.
- `shared/` — the catalogue and protocol are the server's contract. Balance
  numbers and new unit types need agreement first; open an issue before the
  pull request, because the server has to play by the same file.
- `agents/` — new tools, better tactics, other models.
- `public/` — pages, styles, the API documentation page.

Anything under `scripts/`, `package.json`, `tsconfig.json`, `.github/` and this
file is generated by the pipeline. Change it and the change disappears; suggest
it in an issue instead.

## House rules

- No new dependencies without a reason that survives a question. The interface
  ships `three` and `cordis`, and that is meant to stay small.
- Comments explain why, not what.
- German or English, in issues and in code. The game's interface is German.
- Never put a token in an issue, a pull request or a test. A token is an
  identity: whoever reads it plays as you.
